Bitcoin full node in Rust for server-side operators

A validating peer with a compact relational archive and in-process Electrum (optional Esplora REST) in one Linux-first binary. Built for wallet backends and infrastructure—not a desktop GUI or pruned lite node.

Why this node is different

Most full nodes organize around a UTXO set and block files. Most Electrum backends are external indexers attached to another node. rbitcoin takes a different path: one process, one archive, wallet indexes included.

Relational archive, no UTXO database

Map-free Class A/B/C tables in the libbitcoin-class tradition: packed transactions, spend annotations, and native scripthash. Transaction index and Electrum index share the same archive footprint—no separate multi‑GiB UTXO chainstate.

Electrum in-process

A single binary for Electrum self-hosting, with optional Esplora REST. There is no second process re-indexing block files. The surface is aimed at wallet clients, not a graphical block explorer.

Pure-Rust scripts · modest RAM

Consensus and script verification run in Rust on rust-bitcoin, with secp256k1 as the only cryptographic primitive. Confirm work stays lookup → load → scripts → write—no multi‑GiB dbcache flushes on the hot path.

Operator-order facts

Approximate figures from a real mainnet archive. The tip moves; treat these as order of magnitude, not a warranty or SLA.

~886 GiB Full archive with txindex and Electrum scripthash Fits ~1 TB-class disks
< ~30 h Initial block download on a laptop-class host With --milestone 0 (full script checks)
Modest RAM During sync—no multi‑GiB dbcache Confirm: lookup → load → scripts → write

Segmented transaction heads keep newer txs hottest under tip traffic. Portable static musl builds target ordinary Linux hosts without a matching glibc. Details on GitHub.

Who it is for

Goals differ from Bitcoin Core: a smaller full archive and a single binary for Electrum self-hosting—not every Core product surface.

Built for

  • Operators running Electrum or Esplora wallet backends
  • Infrastructure that wants validation and indexing in one process
  • Linux servers with roughly terabyte-class disk for a full archive
  • Engineers who want a transparent pure-Rust consensus path

Not a fit today

  • Desktop wallets, mining, or a graphical UI
  • Pruned or low-disk “lite” deployments
  • Graphical block explorers and catalogue-style search

Start on signet

Soak on signet before any mainnet cutover. On-disk format and APIs remain unstable until 1.0. Source and portable musl builds are on GitHub.
