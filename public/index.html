Bitcoin full node in Rust for server-side operators

A validating node for Linux servers. The store is a compact full archive, not a UTXO database. Consensus uses rust-bitcoin and libsecp256k1. Full Electrum wallet serving (including silent payment tweaks), Esplora, and a Core-class JSON-RPC subset are optional.

Why this node is different

One process validates, archives, and can serve wallet clients. There is no UTXO database and no separate indexer.

Relational archive, no UTXO database

Outputs, spend annotations, and a transaction index are the store. Confirm and mempool prevouts read that archive—not a mutable UTXO set and not a multi‑GiB dbcache flush.

Full Electrum wallet serving

Electrum lives in-process: history, unconfirmed, broadcast, fees, and silent payment tweaks. Optional Esplora REST covers the same wallet role. Not a graphical explorer.

rust-bitcoin · libsecp256k1

Wire and transaction types come from rust-bitcoin. ECDSA and Schnorr go through libsecp256k1. Script evaluation is in-tree Rust. There is no libbitcoinconsensus dual-eval.

Optional Core-class JSON-RPC

A documented subset over HTTP (--rpc-listen, cookie or user/pass). Chain, mempool, raw tx, and estimatesmartfee—not wallet, mining, or a UTXO-set scanner. Prefer Electrum or Esplora for script history and wallet clients.

Storage

Full archival only. Size grows with the chain—plan on a 1 TB-class volume, not a published byte count. Split hot and cold if you have more than one class of disk.

1 TB-class Full archive, including indexes you enable No prune. Tip moves; not a storage SLA.
< 250 GB hot Even with full indexes Outputs, spends, heads, optional scripthash
Hot / cold --datadir-cold for a second volume Inputs and witness can sit on HDD

Without --datadir-cold, everything lives under --datadir. Modest RAM during sync (no multi‑GiB dbcache). Reproducible static musl builds from a pinned Nix flake are byte-identical for a given revision. No published release binaries yet.

Who it is for

Aimed at operators who validate, store, and serve wallet clients. Not a Bitcoin Core replacement, and not a pruned or desktop node.

Built for

  • Operators who want full Electrum, including silent payment tweaks, in the same process
  • Infrastructure that needs a documented JSON-RPC subset next to the archive
  • Linux hosts with 1 TB-class disk; --datadir-cold if you have two storage classes

Out of scope

  • Desktop wallets, mining, or a graphical UI
  • Pruned or low-disk “lite” deployments
  • Graphical block explorers and catalogue-style search

Why it exists

A rust-native consensus implementation should exist next to Core and btcd, on a compact archive instead of a UTXO set, serving Electrum including silent payment tweaks. Why rbitcoin exists.

Get the node running

Clone the source and build a reproducible musl binary with Nix. Mainnet use is reckless; consensus divergence is likely. If the node is useful, fund continued work.
