Tables grow with pread/pwrite and fallocate; the kernel page cache is L0. Class A/B/C are not process-mmap’d, and there is no LevelDB UTXO chainstate.

Class A / B / C

Three roles in one store. How each class mutates matches its job.

Class A — archive

Canonical history: headers and packed full transactions (body plus dense index). Bodies append; visibility is published through high-water marks and heads (allocate-then-publish). Identity is a dense create_fk, with txids in a side file—not a fat key on every row.

Class B — indexes (optional)

Forever-open Electrum scripthash when you pass --shindex: thin create_tx_fk lists (inline or 4 KiB pages). That is extra disk and write cost you choose—not a faster IBD. Query time joins A and C. Off by default.

Class C — tip

Best-chain visibility: confirmed[], strong flags, transaction heights, and per-header ranges. Tip advance is the commit. Spentness is recorded as annotations on create outputs (with rare multi-spender lists)—not by deleting coins from a UTXO bag.

How lookups work

Paths operators and wallet backends hit most often.

Question Path
txid → transaction Segmented tx.head (25-bit open address; sealed segments fuse8-gated) → create_fk → tx.idx / tx.body; verify identity via txid.body
height → block txs confirmed[h] → header_fk → contiguous Class A range from header_txs_first + header_txs_count
scripthash history Requires --shindex. Class B SH head/pages → create fks → join packed outs + Class C height / spentness (+ mempool for unconfirmed)
Is this output spent? Annotation on the create output (and multi-list only when needed)—no separate UTXO hash table as truth
Serve historical block wire Reconstruct from packed Class A txs; recent tip window may hit the wire ring

Tip-hot transaction heads

tx.head/ is a segmented, keyless address table of dense create foreign keys: fixed 25-bit open segments with relative ids, roll at load or soft span, and binary fuse8 only on seal. Open segments always probe; sealed segments are fuse-gated. Newer transactions resolve hottest, so tip-local traffic wins without a multi‑GiB open hash of every outpoint.

Map-free I/O

Class A/B/C are ordinary files: pread/pwrite, fallocate capacity growth, page cache as L0. The process does not mmap the archive tables. Optional bulk io_uring covers some denserel paths; table transport stays file-descriptor based and page-coalesced.

Compared with Bitcoin Core (store)

Primary truth is the archive and annotations, not a UTXO chainstate.

Concern rbitcoin Bitcoin Core (typical)
Primary store Map-free Class A/B/C tables; page cache as L0 blocks/blk*.dat + undo + LevelDB chainstate (UTXO)
Historical blocks Reconstruct from packed tx archive; tip wire ring Serve raw blk / undo
Spentness Annotations on creates; no mutable UTXO set as truth Coins view / UTXO mutations
Txid lookup Segmented tip-hot heads + dense body; full archive index included Optional txindex; otherwise not the hot path
Electrum / Esplora In-process; require --shindex (off by default) External indexer over Core (Fulcrum, ElectrumX, …)
JSON-RPC Optional documented subset; cookie or user/pass; no wallet/mining Large Core surface including wallet and mining
Script verification Pure Rust in-tree (secp256k1 via rust-bitcoin) libbitcoinconsensus / C++ interpreter

Compared with external Electrum indexers

The validating node and the archive share one process; Class A is authoritative.

Concern rbitcoin Typical external indexer
Data source Validating node + archive in one process Reads Core RPC or blk files after the fact
Scripthash index Opt-in --shindex; written on confirm; join at query Separate DB built by scanning history
Unconfirmed Mempool attached in-process Depends on Core mempool RPC
Consensus This binary validates blocks/scripts Trusts the node it indexes

Full archival only. There is no pruning option. The store assumes a complete transaction archive with a transaction index. Scripthash is extra cost when you enable --shindex. Format is unstable until 1.0; see SCHEMA.md for the current tables.
