About

Why this node exists, who built it, and how to reach the project. Validate, archive, and serve Electrum wallets—including silent payment tweaks.

Why rbitcoin exists

I wanted a rust-native, performant Bitcoin consensus implementation to exist. Not a wrapper around libbitcoinconsensus, and not Core’s C++ interpreter with a Rust coat. Types and wire come from rust-bitcoin. ECDSA and Schnorr go through libsecp256k1. Script evaluation is in-tree Rust.

Several clients can share one consensus library. That is useful for mission-critical services that want a well-known engine. Independent implementations are useful for a different reason: Core, btcd, and rbitcoin reading the same chain under different code can expose gaps between the understood rules and the real rules. rbitcoin is that second bet.

The store is the other half of the idea I had sat with for years: a compact relational archive with no UTXO database. Full history. Full script checks when you ask for them. Disk that belongs on a 1 TB-class drive, with under 250 GB hot even with wallet indexes. --datadir-cold puts rarely-read inputs and witness on a second volume. Confirm should be limited by libsecp256k1, not by a coins database and a multi‑GiB cache flush.

The node I wanted to run also had to serve wallets. Electrum in the same process, including silent payment tweaks; Esplora if you want REST; a documented Core-class JSON-RPC subset if you need it. Not a desktop wallet and not a block explorer.

I specified that design and directed the implementation — Brandon Black (@reardencode). First-party code was written with AI assistance (Grok / xAI). Building it also documented concrete rust-bitcoin limitations that can be fixed upstream. None of that reduces the seriousness of consensus, P2P, or Electrum integrity, or how bugs should be reported. See the node SECURITY.md for authorship and review expectations.

What the node is

A validating Bitcoin full node for Linux servers. libbitcoin-class relational archive—no UTXO database. Full archival only. Reproducible static musl builds from a pinned Nix flake. Experimental 0.x: mainnet use is reckless; consensus divergence is likely.
