Security

Full-node software for production server-side use. Until 1.0, treat mainnet as early production / high-scrutiny.

Report vulnerabilities privately to security@reardencode.com. Do not open a public GitHub issue for unfixed remote, consensus-critical, or data-integrity bugs.

0.x expectations

  • On-disk format and APIs are unstable until 1.0.
  • Prefer a signet soak before first mainnet cutover.
  • There is no multi-year LTS branch yet; security-relevant fixes are prioritized on 0.x.
  • The software is not prime time yet—rapid progress, high scrutiny.

Milestone / script checks

Default mainnet --milestone skips script/sig checks at or below the configured height (assumevalid-style speed tradeoff). Prevouts, double-spend, maturity, and fees still run. Use --milestone 0 for full historical scripts. This is an honest tradeoff—not a claim that all historical scripts were checked under the default flag.

In scope (node)

  • Consensus and script: accepting invalid chain data or rejecting valid data
  • P2P (BIP324 v2 only): DoS and misbehavior handling
  • Electrum and Esplora wallet-client backends: integrity and application DoS limits
  • Store / archive: corruption or incorrect spend/scripthash results that mislead a wallet backend

Full policy: node SECURITY.md. Report against a git commit (and binary digest if you built musl static).

Out of scope (for security@)

  • Feature requests, IBD performance, non-sensitive crashes → ordinary issues / CONTRIBUTING
  • Compromised operator hosts, reverse-proxy misconfiguration, third-party wallets outside the tree
  • Do not send seed phrases or private keys

This website

rbitcoin.org is static HTML/CSS/JS with no backend. Serious site issues (e.g. XSS in checked-in scripts) → security@reardencode.com. Typos and broken links can be ordinary issues or PRs on the site repository.
